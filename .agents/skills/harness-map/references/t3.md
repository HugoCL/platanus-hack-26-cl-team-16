# T3 Code

T3 tools sit alongside those of the active provider. Follow that provider's skill directories and model rules. Extra T3-specific skill search paths are **UNCONFIRMED**. If a skill is missing, check the provider's loaded skills and read the committed `.agents/skills/<name>/SKILL.md` directly.

- **Models and workers.** Call `orchestrator_capabilities` to resolve the provider, model, and option values. Call `delegate_task({ task, role, target: { model, options: { effort } }, isolation, mode })`, adding the provider identifiers returned by the catalog when switching providers. The child gets only its brief. Use `isolation: "shared"` for readers and `"worktree"` for writers who can start from the committed base. When host rules prefer native same-provider children, use the active provider's tool for those. `t3_thread_launch` and `create_threads` are for explicitly requested top-level threads.
- **Results.** Use `mode: "wait"` when the turn depends on the result, otherwise follow the asynchronous delegate's returned continuation or completion notice. `task_status({ taskId })` exists, but follow the host's continuation rules. For a top-level thread, use `t3_thread_wait({ threadId })` when available. Ask questions through the active provider's question tool.
- **PRs.** Use `pull_request_create` when available. After creating a PR by another authorized route, use `link_pull_request` with its full URL if offered. The owning thread calls `watch_pull_request` with the PR URL when asked to monitor, then yields for events. Call `unwatch_pull_request` when handing it back. Check live schemas.
- **Attachments.** `t3_attachment_prepare_upload` returns an `uploadUrl`. POST the exact bytes there, then use `t3_thread_send_attachments` for a thread message. These tools attach evidence to T3 threads. Use the forge path in [git conventions](../../git-conventions/SKILL.md) to put evidence in a PR description.
- **Issues.** If exposed, call `create_issue` with the ticket title and body using the live schema. Use `read_issue` or `list_issues` to look up reports. Check for an update tool or use the connector for the issue's tracker.
